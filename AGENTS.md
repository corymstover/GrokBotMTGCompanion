This repository supports several MTG Companion workflows. The instructions below govern only work on the **Grixis Commander Encyclopedia's M6/M7 refinement and the 62 canonical decks**. They do not authorize changing unrelated MTG Companion work.

## Mandatory Grixis M6 review protocol

**Read `grixis/M6 Commander-First Single-Deck Review Standard.md` and `data/grixis/m6/single_deck_depth_tracker.json` before starting or resuming authored deck-review work.** These are persistent workflow instructions and a source-bound progress ledger, not chat memory.

1. **One commander/deck at a time.** Review the single current deck through full substantive strategic investigation, source/rules verification, case-specific candidate comparisons, and a completed immutable review artifact *before starting the next deck*. Never substitute a batch of shallow top-one-swap judgments for a deep review. Consecutive completed single-deck reviews may happen in one agent session without user approval between them.
2. **Follow the exact canonical tracker order** from `corymstover/grixis-commander-encyclopediaGPT/refinement/Deck_Refinement_Tracker_2026-10-12.csv` unless Cory explicitly changes the order. Start with the first `PENDING` deck in the live deep-review tracker (initially `Abaddon_the_Despoiler`); independently confirm ordering and current approval hashes before new work.
3. **Distinguish counts:** M6.4 already has 62/62 narrow, source-linked *authored candidate reviews* from Cycles 112–131. This is NOT 62 comprehensive deck-depth reviews. The deep-review tracker begins at **0/62** and advances only after substantive evidence passes the checklist and the deck-specific audit. Do not reset or inflate the historical M6.4 completion, Pass C or Phase B.
4. For each review, examine the entire approved **100-card baseline**, deck's distinct strategy and natural ceiling, engine/core, all meaningful role and mana-base weaknesses, relevant ranked and *off-ranking* candidate alternatives, multiple reasonable cuts, exact Oracle and interactions, costs/turns, realistic adversarial scenarios and applicable tests. Write a complete per-deck decision record and a justified stop condition. A single candidate assessment is never by itself enough.
5. The engineering repo is evidence-only. **Never modify, unlock, replace, unapprove or approve a canonical decklist, change its approved SHA, apply a proposed swap, alter the project exception registry, certify an independent Pass C, or declare milestone acceptance without Cory's explicit authorization.** Future-release, Lutri, and other project-authorized exceptions must be distinguished from official Commander legality. A technically passing simulator is not proof of strategic improvement.
6. Source-bind each deep review to the live canonical authority and record actual tests, assumptions and unresolved issues. Test and merge engineering-only changes only after PR exact-head CI passes. If the current deck is blocked, record the precise unresolved dependency and stop or address it; do not skip it by pretending it passed.
7. **Only after ALL 62 comprehensive authored reviews meet this separate standard** prepare the finished package for a genuinely independent GrokBot Pass C; seal GrokBot's blind/reduced-exposure first findings before exposing ChatGPT's verdict, disclose prior involvement and record actual disagreements. Earlier advisory GrokBot opinions are not auto-qualified.
8. Preserve review progress durably after each finished deck; on continuation recover live GitHub and resume at the actual first unfinished ID. **Never say work is continuing after the session ends unless an external worker is really running.** Do not recreate architecture or rerun a large research pipeline just to continue reviews.

Standing owner authorization covers engineering-only work and consecutive deck-specific authoring. Owner intervention remains required for canonical card swaps and final acceptance.
